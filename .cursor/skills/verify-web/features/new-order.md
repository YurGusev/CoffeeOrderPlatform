# Новый заказ

Страница `/app/orders/new` создаёт черновик для уже выбранного клиента.
Заголовок «Новый заказ». Страница собрана в `apps/web/src/browser/routes/NewOrderPage.tsx`.

## Sub-features

- `new-order-without-customer` не покрыто. Без годного `customerRef` виден текст «Сначала выберите клиента».
- `new-order-create` не покрыто. С годным `customerRef` видна кнопка «Создать черновик».

## How to get to it (user POV)

- После сессии открыть `/app/orders/new`.
- Нажать «Новый заказ» в навигации.
- На странице клиентов нажать «Выбрать» или завершить «Создать и выбрать». Адрес тогда содержит `customerRef`.

## Driving it with verify-web

Preconditions:

- Нужен `GET /auth/session` со статусом 200. Этот рычаг его не получает.
- Сценарии `new-order-without-customer` и `new-order-create` остаются `not-covered`.

- **Не продолжать на экране входа.** Закрытый путь `/app/orders/new` в `session-new-order-closed` не является прохождением этой фичи.
- **Без клиента, когда сессия уже есть.** Открыть `/app/orders/new`. Виден заголовок «Новый заказ» и текст «Сначала выберите клиента». Есть ссылка «поиск клиентов». Кнопки «Создать черновик» нет.
- **С клиентом, когда сессия уже есть.** Открыть `/app/orders/new?customerRef=<cus_...>`. Виден текст «Выбранный клиент» и кнопка «Создать черновик». После успеха адрес становится `/app/orders/<orderRef>`.

## Gotchas

- Годный `customerRef` в коде совпадает с `^cus_[0-9A-HJKMNP-TV-Z]{26}$`.
- Сам идентификатор на экране не доказывает, что Customer owner принял клиента. Страница прямо говорит, что клиента повторно проверит сервис Customer.
- Ошибка создания показывается через `ProblemAlert`. Этот рычаг её не вызывает.
