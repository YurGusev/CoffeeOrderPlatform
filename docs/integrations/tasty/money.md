# Tasty: цена и точность

Историческое исследование одного аккаунта 25 октября 2026 года не является
контрактом поставщика. [Сводка](../../../evidence/tasty/money/observations.json)
содержит endpoint, интервал UTC, область аккаунта, selectors и SHA-256 исходных
файлов Obsidian. Это обезличенный производный набор выбранных полей, не raw
HTTP response. Числа записаны после JSON parsing; исходные raw numeric lexemes
не сохранены и восстановить их из этих данных нельзя.

| Денежный факт | Наблюдение и граница |
|---|---|
| Цена offer | `offer-prices`: в начальном срезе 5 из 568 offer имели дробную цену, среди наблюдавшихся значений `490.8`, `604.5`, `425.8`. Требование целых рублей не подтверждено. |
| Цена строки и скидка | `offer-line`, `cart-ten`: в исследованных обычных строках cart line `price` отражала исходную цену offer. Для десяти позиций сумма без скидки `7229`, `meta.price=5060.3`, `meta.discount=30`. Это наблюдение для одного аккаунта и состава корзины, не универсальная формула скидки. Индивидуальные условия, исключения и объёмные правила **NOT_PROVEN**: нужно определение правил поставщика и сопоставимые наблюдения для разных условий и составов корзины. |
| Итог cart | `cart-float-tail`: после parsing в `meta.price` наблюдалось `1638.6999999999998`. Это значение источника после parsing, не вычисленный здесь пример. Итог не является доказанным invoice/checkout total; закупочная цена отдельной строки из общего total **NOT_PROVEN**. Нужно подтверждённое распределение скидок, округления и итогов по строкам. |
| Валюта | `currency`: самостоятельное поле currency у offer в выбранных responses не наблюдалось; UI показывал рубли. Currency mapping для API **NOT_PROVEN**: необходимо явное подтверждение валюты поставщиком для соответствующего аккаунта и ответа. |
| Клиентская цена | Она не наблюдалась как цена CoffeeOrderPlatform в этих данных. Pricing рассчитывает её по собственной policy и quote, а не приравнивает к offer или cart total; см. [спецификацию Pricing](../../launch/16_PRICING_IMPLEMENTATION_SPEC.md). |

**Decimal → minor: NOT_PROVEN.** Для достоверной закупочной цены в копейках
нужны исходный точный денежный формат/lexeme, подтверждённая валюта и правило
поставщика для масштаба и округления, в том числе для дробных значений и
распределения скидки. До принятия такого правила неоднозначную цену нельзя
нормализовать; молчаливое округление запрещено. Исторические десятичные записи
в сводке иллюстрируют значения после parsing и не доказывают исходную точность.
Закрытие исследования не означает готовность Pricing и не меняет существующую
политику RUB, наценку, PricingQuote или checkout.
