# NGINX: нормативный контракт публичного транспорта и прикладной авторизации

Статус: target authority #159 / [ADR-0031](../adr/ADR-0031-nginx-transport-and-application-auth.md). **Не описание текущих Compose/config и не runtime admission.** Реализация и active cutover — #160/#161/#162. Существующие `client-v1` OpenAPI, `20_REALTIME_SSE_IMPLEMENTATION_SPEC.md` и `24_SERVICE_IDENTITY_AND_DELEGATION.md` сохраняют ownership своих contracts. Ни один provider/agent/internal route не разрешён этой задачей.

## 1. Место в топологии и точный внешний inventory

Browser → public TLS `edge-nginx` → для protected маршрута private `GET /_edge/authorize` (`edge-gateway:4000`) → mTLS к `api-public:4050` или `realtime-gateway:4401`. Для auth flow nginx обращается к тому же private Edge **без** auth subrequest. Immutable React files обслуживаются локально; Node `web` runtime и Node Edge reverse proxy удаляются **только** при атомарном #162. У upstream нет публичного host port. Upstream targets берутся из native runtime profile, не из Host/URL браузера.

| Метод и exact path | Target | Защита/семантика |
|---|---|---|
| `GET,HEAD /` | nginx | 303 на `/app/customers`, без HTML fallback других surfaces |
| `GET,HEAD /app/**` | nginx immutable SPA | `index.html` только для допустимых deep links; никаких private данных в HTML; API требует auth отдельно |
| `GET,HEAD /assets/**` | nginx immutable hashed files | неизвестный asset → 404, никогда SPA |
| `POST /api/client-v1/customers` | api-public | `createCustomer` |
| `GET /api/client-v1/customers` | api-public | `searchCustomers` |
| `GET /api/client-v1/catalog/products` | api-public | `searchCatalogProducts` |
| `POST /api/client-v1/pricing/quotes` | api-public | `createPricingQuote` |
| `POST /api/client-v1/orders/drafts` | api-public | `createOrderDraft` |
| `PUT /api/client-v1/orders/{orderRef}/items/{itemRef}` | api-public | `upsertOrderItem` |
| `DELETE /api/client-v1/orders/{orderRef}/items/{itemRef}` | api-public | `removeOrderItem` |

| `GET /auth/login`, `GET /auth/callback`, `POST /auth/logout` | edge-gateway | exact application session/OIDC handlers; никогда не auth_request |

Только exact methods из таблицы и approved path parameters из `client-v1.yaml`; query string передаётся только определённому target, не расширяет operation inventory. `HEAD` не является implicit alias API/`events`/auth. `/health/ready`, `/metrics`, ops доступны только private monitoring plane; ни `/api/internal-v1/**`, ни `/api/agent-v1/**`, ни `/api/provider/**`, `/admin/**`, `/auth/**` wildcard, `/events/**`, VK/PSP placeholders, ни неизвестные `/api/**` не получают proxy/SPA fallback. У чужого метода/пути — 404/405 с запретом на попадание в owner и без HTML. Нормативный список API методов/операций читается из OpenAPI и проверяется против приведённой таблицы при генерации; второй ручной runtime registry запрещён. `X-HTTP-Method-Override` и аналоги не допускаются. Владельцы future provider/agent routes принимают exact path и signature/raw-body ACK семантику отдельными PR (#76/#77 для W2 и #98/#99 для W3), без browser session; nginx никогда не подтверждает callback до durable owner intake.

## 2. Browser identity и session profile

Единственный target W1 browser auth — OIDC Authorization Code + PKCE (S256) через приложение. `GET /auth/login?returnTo=/app/...` создаёт одноразовые `state`, `nonce`, PKCE verifier в ограниченном in-memory хранилище Edge, 303 к заранее утверждённому exact issuer authorization endpoint. `GET /auth/callback` по exact зарегистрированному redirect URI проверяет state, nonce, code exchange, подпись ID token через JWKS, точные issuer/audience, alg allowlist, `exp/nbf/iat` и actor/permissions mapping; после успеха 303 только на локальный `/app/` path. Авторизатор не получает callback от произвольного host, не следует redirects к неизвестному origin и не передаёт access/refresh/ID tokens браузеру. Браузерный bearer token на `client-v1` в W1 не поддерживается; Authorization header с неизвестным bearer → 401, не альтернативный trusted actor. Проверка JWT здесь относится к OIDC ID token на callback, а не к compact Ed25519 actor assertion (последний **не JWT**).

После callback Edge хранит bounded, expiring `sessionId → actorRef, permissions, csrfSecret, expiry` только в private process memory; cookie `__Host-coffee-session` содержит криптостойкий непрогнозируемый opaque ID, `Secure; HttpOnly; SameSite=Lax; Path=/` без Domain. Отдельный `__Host-coffee-csrf` содержит session-bound случайный token (`Secure; SameSite=Lax; Path=/`, без Domain и HttpOnly), который браузер передаёт в `X-CSRF-Token`; значение не является identity и не даёт доступ без HttpOnly session. Single Edge replica; рестарт/потеря памяти инвалидирует сессии (повторный login), нет sticky/multi-replica обещаний и нет hidden Redis/DB. TTL 15 минут абсолютный, не sliding; не хранить provider tokens после callback. `POST /auth/logout` требует активную session, same-origin `Origin` и `X-CSRF-Token`, немедленно удаляет session на сервере, истекает обе cookie и отвечает 204; OIDC global logout/revocation без утверждённого provider contract не обещаются. Каждый cookie-auth POST/PUT/DELETE, включая logout и replay-only lookup, требует exact same-origin `Origin` и неповторяемый при смене сессии `X-CSRF-Token`; проверка token — constant-time против session secret и против CSRF cookie. Static SPA не раскрывает private state; cross-origin CORS с credentials запрещён, cookie не заменяет server-side permission.

`GET /auth/session` — отдельный exact public route nginx → private `edge-gateway`, без `auth_request` (иначе рекурсия); сам handler проверяет текущую HttpOnly session, возвращает **только** server-derived `{actorRef, expiresAt}` с `Cache-Control: no-store`, typed 401 при expired/invalid session, без токенов, permissions, cookie rotation, продления TTL или побочного эффекта. Ответ от прошлой сессии браузер отбрасывает. До первой мутации #9 получает эту actor-привязку доверенным ответом и фиксирует её только в metadata pending intent; UI-сохранённый actorRef не становится полномочием. Если status недоступен, не отправлять новую команду без actor-bound pending metadata. При истечении session/401 немедленно скрыть private cache и закрыть SSE, **но не помечать отправленный pending intent успешным/неуспешным**: сохранить его metadata заблокированной для дальнейших вызовов; новый login и новый `GET /auth/session` для *того же* actor только разблокируют **явный** bodyless `Idempotency-Replay-Only: true` lookup с прежним key/method/path и CSRF текущей сессии. Исполняющую команду не повторять. Другой actor или утерянные metadata → очистить прежний private state с предупреждением о неизвестном исходе и направить на owner recovery; не показывать ему данные прежнего пользователя. Owner заново проверяет `(actorRef,scope,key)`, текущие permissions и resource access. При **явном logout** сохраняются действующие [правила предупреждения и очистки](26_BROWSER_COMMAND_RECOVERY.md); pending intent не переносится к другому actor. Logout не гарантирует немедленной серверной ревокации уже открытого SSE: браузер закрывает его сразу, а realtime проверяет `exp` подписанного assertion каждые 30s; это отдельно тестируется и не заявляется production PASS.

`returnTo` допускает только нормализованный local `/app/` deep link без scheme/host, backslash, encoded separators/dot segments, double decode или control chars; default `/app/customers`; state и nonce используются один раз с deadline 5 минут. Конкретные OIDC issuer, client ID, callback origin, trusted algorithms/JWKS URI, actor claim и permission mapping — обязательные проверенные input values одного `config/platform.yaml`, client secret только SOPS/authorizer scope. Действующий config их **не содержит**: production login/final acceptance закрыты до внешнего provider evidence и binding #162. Не выдумывать IdP URL/account/keys и не трактовать `edge.oidcClientSecret` как готовый профиль. JWKS кешируется в памяти по bounded TTL ≤5 минут с принудительным refresh при неизвестном `kid` один раз (без trust on failure); stale/недоступный JWKS либо запрещённый alg/ключ → login fail-closed, не выпускать session. Rotation принимает только текущие доверенные keys за bounded overlap из provider profile. In-flight авторизованные сессии не продлеваются без повторного login; корректность claim revocation до 15 минут — открытый риск для owner admission.

## 3. Private auth-request и receiver

`GET /_edge/authorize` принимает пустое тело только через mTLS `edge-nginx` на private network; nginx `location` помечен `internal`, не включён во внешний route inventory. В nginx auth subrequest — `proxy_pass_request_body off` и очищенный `Content-Length`. Вход: только оригинальные method/raw target, trusted scheme/host из `platform.publicBaseUrl`, request/correlation ID, traceparent и **только** две cookies `__Host-coffee-session`, `__Host-coffee-csrf`, `Origin`, `X-CSRF-Token` (для cookie mutations); `Authorization` на browser API в W1 запрещён. Никакие browser `X-Actor-*`, `X-Service-*`, `X-Forwarded-*`, `X-Original-*`, `X-Transport-*`, `X-HTTP-Method-Override`, вручную переданные operation/audience и дублированные security headers не становятся доверенными. Reject ambiguous/malformed `%` escapes, encoded slash/backslash/dot, dot segments, duplicate slash, double decoding, CRLF, overlong targets и несовпадающую nginx/receiver normalization **до** вызова business upstream; #160/#161 проверяют raw-versus-normalized behavior на реальном nginx, а не только в Fastify fixture.

Authorizer сопоставляет исходный метод+path с OpenAPI registry, выводит actor/permission/operation, проверяет session, CSRF и route; signer выпускает текущий compact Ed25519 `X-Actor-Context` c `iss=edge-gateway`, `originalIssuer=edge-gateway`, `aud=api-public` для API или `realtime-gateway` для SSE, `sub`, permissions, `operationId`, correlation/trace, `iat/exp/jti/kid`. `exp` ≤ min(now+60s, session expiry), не принимать `exp≤iat`. Ответ **ровно 204**, только trusted assertion/IDs; 401 = неаутентифицирован/expired, 403 = no permission/CSRF. Нет Set-Cookie/refresh, body, redirects, auth cache или вызова business upstream. nginx `auth_request` по умолчанию принимает любой 2xx: generator обязан обеспечить **дополнительную** проверку именно 204 и непустого assertion до proxy; malformed/отсутствующий context также проверяет receiver криптографически. Нестандартный status, network timeout, TLS failure, invalid header → 503 `AUTHORIZER_UNAVAILABLE` без вызова target; не заменять отказ успешным пустым actor.

К business target nginx пропускает только Host из trusted config, собственный request/correlation ID, `traceparent`, валидный `Content-Type`, `Accept`, contract-required `Idempotency-Key`, `If-Match`/`If-Match-Version`, `Idempotency-Replay-Only`, и для SSE `Last-Event-ID`; body API передаётся byte-preserving и только для разрешённого метода. Подписанный `X-Actor-Context` берётся **только** из ответа текущего subrequest. Cookie, Authorization, Origin/CSRF, исходные actor/forwarded/service headers и любой `Set-Cookie` из owner responses не прокидывать. Content-Type/Problem Details и business status от owners не переписывать (`proxy_intercept_errors off`). `api-public` требует transport SAN caller=`edge-nginx` + issuer=`edge-gateway` + exact operation/correlation/audience/permission/TTL; владелец после `api-public` получает прежнюю signed delegation. Realtime gateway требует caller=`edge-nginx`, issuer=`edge-gateway`, audience=`realtime-gateway`, permission и rechecks auth expiry каждые 30s. Параллельный old `edge-gateway` transport caller после #162 запрещён.

Auth отказ 401/403 наружу — локальный RFC 9457 JSON `application/problem+json` с постоянными codes `AUTHENTICATION_REQUIRED`/`AUTHORIZATION_FORBIDDEN`, включая CSRF отказ (`CSRF_VALIDATION_FAILED`); `WWW-Authenticate` из auth subrequest не передаётся browser cookie flow. Инфраструктурный auth отказ/timeout → 503 `AUTHORIZER_UNAVAILABLE`; собственные transport ошибки upstream 502/503/504 → RFC 9457 `UPSTREAM_UNAVAILABLE`, `Cache-Control: no-store` и correlation ID, без HTML/redirect или необработанного nginx body. Защищённые API/SSE не получают login redirect; у SSE ошибки идут **до** stream headers. После старта SSE ошибка передаётся только закрытием/reconnect, не переписыванием частичного event stream. Auth result и error responses не cache-ятся, authenticated body/headers никогда не log-ятся.

## 4. TLS, deadlines, capacity и эксплуатация

nginx один владеет `edge.tlsPrivateKey`/`edge.tlsCertificate` (public hostname), не signing key. `edge-nginx` получает **отдельный** internal client certificate `spiffe://coffee-platform/<environment>/edge-nginx`; авторизатор, `api-public` и `realtime-gateway` — каждый свою URI SAN и exact DNS SAN `<runtime>.<environment>.svc.coffee-platform.internal`. Provisioning подписывает exact DNS + URI для того же runtime/env (без wildcard/другого service), сохраняет 24h TTL, rotation за 6h и 12h overlap. nginx `proxy_ssl_verify on` + trusted CA + explicit SNI/`proxy_ssl_name` exact runtime DNS; Node targets требуют nginx URI caller, не доверяют одному только CA/DNS. При неправильном DNS/env/SAN, expired/revoked cert/unknown CA — fail closed. Никакого shared private key. `config-bootstrap` материализует PEM только в scoped tmpfs; nginx не видит CA private, actor signer, OIDC client secret или DB/provider keys, Edge не видит public TLS private. Reload проверяет новый config и новые handshakes, bounded drain старых connections; emergency revoke закрывает старые connections, не ждёт только нового handshake.

Target values **до capacity измерений**, со scope `config/platform.yaml` после #162:

| Ресурс/время | Начальная целевая граница | Владелец доказательства |
|---|---|---|
| auth absolute processing | 500 ms (без silent refresh/JWKS discovery); неуспех fail-closed | #160/#162 |
| API nginx connect / read / send inactivity | 1s / 6s / 6s; не end-to-end timer | #161/#162 |
| `api-public` absolute request | существующие 4500 ms от его входа; Edge прежний 5s total timer **удалён** | #61/#162 |
| SSE read inactivity | ≥45s при 15s heartbeat; stream без total 5s timeout | #12/#162 |
| API body / total header / raw target | ≤1 MiB / ≤16 KiB / ≤2 KiB; ниже утверждённого owner limit не повышать | #161/#162 |
| admission | ≤256 concurrent API, ≤320 auth subrequests, ≤512 SSE **до** soak; independent budgets, 503 до SSE headers | #161/#162/#12 |
| native nginx normal limits | 2 vCPU / 512 MiB RSS / 16384 FD / 8 MiB scoped tmpfs; no body-on-disk outside bounded tmpfs | #161/#162 |
| reload overlap host reserve | ≥32768 FD / 1 GiB RSS на старые+новые workers; drain/FD safety measured | #162 |
| 5000 SSE connections | **target**, не начальный admission и не PASS; пересчитать FD≈2 sockets/stream + API/auth/keepalive и reload overlap, измерить RSS/CPU | #12/#13 |

Новый browser end-to-end SLO начинается при первом байте принятого публичного запроса и заканчивается доставкой последнего байта обычного API response; измеряется на #13, **не объявляется равным 5s** прежнего Edge timer. Authorizer absolute 500ms, API absolute 4500ms и nginx idle 6s относятся к разным границам и не складываются в обещание полного SLA. `proxy_next_upstream off` для auth/API/SSE и любых будущих callbacks; nginx никогда не повторяет потерянную mutation и не cache-ит protected responses. Browser/owner recovery сохраняют `Idempotency-Key` и expected version по исходным contracts.

SSE: `proxy_http_version 1.1`, очистка hop-by-hop `Connection`, `proxy_buffering off`, `proxy_cache off`, compression off, `X-Accel-Buffering: no`; `Last-Event-ID` проходит без подмены, events лишь invalidation/refetch, один realtime instance, slow-client cleanup/queue budget принадлежат #12. Разрыв TLS/reload вызывает reconnect с новой auth проверкой и owner refetch, не replay эффекта. При 512 initial cap #12 обязан провести transport-inclusive soak и принять повышение до 5000 отдельно.

## 5. Config authority, telemetry и acceptance

Proposed native runtime schema (`#161/#162`, **не** текущий `config/platform.yaml`): `services.edge-nginx.kind=native-nginx`, exact listen/hosts/targets/route inventory reference, health, TLS + per-surface limits/timeouts/admission, `secretRefs=[edge.tlsPrivateKey,edge.tlsCertificate,security.serviceTransportKeys.edge-nginx]`, non-root, read-only, drop caps, scoped tmpfs; `services.edge-gateway.kind=node-authorizer` получает свой signing/OIDC/client transport scope, auth-only listener, no business egress. `web` отсутствует в runtime inventory, `apps/web` build остаётся. Для nginx нет Node Permission Model; native network/filesystem enforcement задаёт image/Compose. Only `config/platform.yaml` содержит значения, only encrypted SOPS содержит secrets, pinned native image/digest only in `config/toolchain-versions.json`. Generated `nginx.conf` и PEM — derived artifacts, deterministic generation plus `nginx -t` и `nginx -V` module check (`auth_request`) у #161; `config-bootstrap` и active schema меняет только #162. Никаких параллельных ручных конфигов или переключения секретов в #159.

nginx native access logs — безопасный fixed JSON allowlist: route template/operation class, method, status, timings, byte count, correlation/request IDs; без raw URI/query, Cookie, Authorization, actor assertion, Idempotency-Key, IP, referrer, User-Agent, body. Raw request-bearing error log не поступает в Collector (runtime `/dev/null`); startup/config-check errors изолированы от traffic. Node authorizer/api-public logs и traces следуют прежней OTLP политике. #64 принимает native access/probe applicability и canary; `GET /health/live` проверяет только nginx transport, private readiness/auth/API/SSE проверяются раздельно; static 200 не является launch readiness. Nginx span без проверенного module не объявлять. Observability loss не блокирует business path.

#160: реальные crypto/session/receiver/negative fixtures, включая `GET /auth/session` и typed 401, отдельный auth contract; #161: pinned image, config, module/TLS/static/SSE/mutation tests, exact session route без auth_request и forbidden methods; #162: единственный active binding, full route/trust/security/rotation/rollback evidence, без old Node proxy и `web` runtime. #9: UI/deep links/browser logout/recovery через nginx; #12: EventSource, SSE fanout, 5000 target soak и reauth; #64: collector/alerts/native applicability; #13: security, browser, accessibility, SLO и launch decision. #76/#77 и #98/#99 (после своих gates): exact future provider ingress; `agent-v1` остаётся private, W1 не содержит заглушек. Coherent rollback возвращает предыдущий verified release bundle целиком, а не один nginx.conf; не включает второй live transport path. Пока нет реальных IdP/trust inputs и последующего evidence — production login и capacity **NOT_RUN**.

Механика auth_request, `proxy_next_upstream`, TLS verify/name и nginx internal locations: официальные [auth_request](https://nginx.org/en/docs/http/ngx_http_auth_request_module.html), [proxy](https://nginx.org/en/docs/http/ngx_http_proxy_module.html), [core](https://nginx.org/en/docs/http/ngx_http_core_module.html) и [reload](https://nginx.org/en/docs/control.html). Это справочник механизма, не свидетельство работоспособности данного deployment.
