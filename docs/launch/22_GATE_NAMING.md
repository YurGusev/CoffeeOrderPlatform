# Имена гейтов запуска

Статус: действует. Относится к `verification/launch/v1/**`, `tools/**`,
`scripts/**`, тестам, конфигурации и документации первого запуска.

## Правило

Гейт адресуется **стабильным slug**, а не номером.

| Правильно                              | Неправильно                        |
| -------------------------------------- | ---------------------------------- |
| `supply_chain`                         | `G12`, `G12_SUPPLY_CHAIN`          |
| `COFFEE_SCAN_CACHE_DIR`                | `COFFEE_G12_CACHE_DIR`             |
| `CONFIG-MIGRATIONS-SOPS-OUTPUT`        | `CONFIG-G08-SOPS-OUTPUT`           |
| `captureKafkaNamespaceArtifact`        | `captureG13KafkaNamespaceArtifact` |
| `// гейт supply_chain собирает образы` | `// G12 собирает образы`           |

Номер `G00…G19` — это **позиция в матрице**, а не идентичность. Он вычисляется
при выводе отчёта из `verification/launch/v1/matrix.yaml` и нигде не сохраняется
как имя.

## Почему

Номер как имя ломается при каждой вставке гейта. Фактическое состояние до
перехода: `G12` стоит между `G07` и `G08`, потому что вставлять гейт в середину
означало переименовать 114 кодов ошибок, 11 env-переменных, 89 символов и
55 файлов с комментариями. В итоге номер перестал соответствовать порядку, а
два независимых списка гейтов (`matrix.yaml` и `EXPECTED_GATES` в
`verification/launch/v1/report.mjs`) разошлись.

## Что разрешено

- `id` в `matrix.yaml` — slug в нижнем регистре: `preflight`, `supply_chain`.
- Вычисляемая метка для читателя: номер позиции и slug, например
  `G08 supply_chain`. Формируется рендерером отчёта из порядка `matrix.yaml`,
  в файлы и контракты не попадает.
- Таблица алиасов для чтения прогонов, созданных до перехода
  (`G12_SUPPLY_CHAIN → supply_chain`). Она живёт в коде отчёта и удаляется,
  когда исторические прогоны перестают быть нужны.
- Ссылки на ADR и issues, где номер является частью исторического имени.

## Что запрещено

- Номер гейта внутри идентификатора, переменной, кода ошибки, имени файла.
- Номер гейта в комментарии как способ назвать гейт.
- Новый гейт с номером в имени.

## Проверка

```bash
node scripts/check-gate-naming.mjs
```

Скрипт сканирует `apps`, `config`, `docs`, `packages`, `scripts`, `tests`,
`tools`, `verification` и падает на новых нарушениях. Исторические
`evidence/**` и `docs/reports/**` не сканируются: они фиксируют прошлые байты.

Существующие нарушения сняты в `scripts/gate-naming-baseline.json`. Снимок
обновляется только в сторону сокращения: каждый этап миграции удаляет свои
записи, целевое состояние — пустой `entries`.

Ключ снимка — `путь|вид|совпадение`. Номер строки в ключ не входит: сдвиг
строк не должен требовать обновления снимка. Обратная сторона — повторное
использование того же символа в том же файле на другой строке проверкой не
отлавливается; для этого случая действует ревью.

## Этапы миграции

| Этап | Содержание                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------------- |
| 0    | Эта конвенция и проверка `scripts/check-gate-naming.mjs`                                                              |
| 1    | `matrix.yaml` со slug-`id` и `order`; `EXPECTED_GATES` выводится из матрицы; evidence по slug; алиасы старых прогонов |
| 2    | env-переменные без номера, чтение старого имени один релиз                                                            |
| 3    | предметные коды ошибок вместо `CONFIG-Gxx-*`                                                                          |
| 4    | переименование функций и тестовых символов                                                                            |
| 5    | комментарии, документация, имена ADR                                                                                  |
