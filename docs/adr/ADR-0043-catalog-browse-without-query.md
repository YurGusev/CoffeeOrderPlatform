# ADR-0043: просмотр активного каталога без поискового фильтра

Статус: решение принято 3 ноября 2026 года; реализация проверяется в #254.

## Основание

Оператору нужно видеть товары каталога до выбора заказа. Обязательный поисковый
параметр блокировал этот сценарий, хотя данные уже доступны в сохранённом
активном snapshot.

Authority: [контракт Catalog](../launch/12_LAUNCH_CONTRACT_CATALOG.md),
[спецификация Catalog](../launch/15_CATALOG_IMPLEMENTATION_SPEC.md).

## Решение

- `GET /api/client-v1/catalog/products` без `query` возвращает первую страницу
  активного persisted snapshot. Это просмотр каталога, а не поиск по пустой
  строке; отдельный route не добавляется.
- Запрос сохраняет `catalog:read`, существующие `availability`, `limit` 1–50
  (по умолчанию 20), cursor и привязку cursor к фильтрам и revision snapshot.
  Отсутствие или повреждение активного snapshot обрабатывается существующим
  fail-closed поведением.
- Если `query` передан, он по-прежнему проходит trim, NFKC-нормализацию,
  lowercase и проверку длины 2–200. Пустое, пробельное или односимвольное
  значение остаётся ошибкой.
- Чтение не выбирает и не создаёт заказ, не вызывает Pricing или provider,
  не меняет наличие и не записывает данные.

## Последствия

OpenAPI допускает отсутствие только query-параметра `query`; совместимость
остаётся расширяющей: существующие запросы продолжают передавать фильтр.
Owner и public API используют существующий Catalog read path и его проверки.
