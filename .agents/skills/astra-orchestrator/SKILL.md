# Оркестрация CoffeeOrderPlatform

Адаптировано из [codex-astra-luna-orchestrator](https://github.com/donvito/codex-astra-luna-orchestrator).
Настройки и запуск Codex: [инструкция проекта](../../../.codex/README.md).
В Hermes эти настройки не применяются; использовать раздел Hermes ниже.

Корневой агент владеет декомпозицией, решениями, интеграцией и итоговой проверкой.
Делегируй только независимую ограниченную часть, пока у родителя есть полезная
работа. Не запускай агентов ради заполнения лимита. Зависимые шаги выполняй
последовательно. Простые задачи решай самостоятельно.

## Hermes

Профиль **CoffeeOrderPlatform** (отображаемое имя; технический ID `default`):

| Роль | Модель | Reasoning | Задача |
|---|---|---|---|
| root / reviewer | `gpt-6-astra` | `low` | Решения, интеграция, финальное ревью и приёмка |
| explorer | `gpt-5.6-luna` | `high` | Найти файлы, проследить код и тесты; только чтение |
| worker | `gpt-5.6-luna` | `high` | Реализовать ограниченный согласованный scope |
| tester | `gpt-5.6-luna` | `high` | Проверить поведение; менять тесты только по поручению |
| researcher | `gpt-5.6-luna` | `high` | Проверить первичные источники; только чтение |

Обе модели используют `openai-codex`. Максимум четыре ребёнка одновременно,
глубина один: дети не создают следующих детей. Лимит — потолок, а не цель.
Роли передаются текстом задачи, не являются отдельными профилями или sandbox.
Ограничение «только чтение» — инструкция ребёнку, не отдельная техническая изоляция.
Настройки моделей живут в профиле Hermes, не в конфигурации приложения.
Явный выбор модели/reasoning в открытом чате может переопределить default;
при несовпадении сообщить его, не выдавать другую модель за Astra или Luna.

Использовать `delegate_task(tasks=[...])` для независимых содержательных задач,
когда разделение снижает нагрузку контекста или время работы. Простые tool calls
выполнять напрямую, механические пакетные операции — через `execute_code`.
Модель и лимиты задаёт текущий runtime; этот навык не создаёт профили и
не переключает конфигурацию во время выполнения задачи.

Передавать каждому ребёнку `goal` и `context`: корень проекта, необходимые
файлы и навыки, границы записи, критерии готовности и русский язык ответа.
У ребёнка нет истории родителя. Работы с вопросами пользователю оставлять root.
Изолированный контекст не означает изолированную файловую систему: write-задачи
выполнять последовательно или в отдельных согласованных worktrees.

Результаты возвращаются асинхронно; пока дети работают, продолжать независимую
работу. Не назначать ребёнку новые профили `worker`/`reviewer`: это роли в описании
задачи, а не параметры Hermes. Не поручать детям дальнейшее делегирование,
публикацию, merge или закрытие issue. Финальное ревью и приёмка принадлежат root.
Проверять существенные выводы по файлам и реальному выводу инструментов, а не
только по итоговому сообщению ребёнка. При недоступном инструменте не имитировать
запуск; выполнить разрешённую работу локально и сообщить ограничение.

## Общие границы

Применяй предметные навыки через coffee-platform-router. Соблюдай руководство
репозитория и выданные пользователем разрешения: этот навык не разрешает внешние записи.
Родитель проверяет diff, результаты обязательных проверок и существенные
замечания; сообщает результат и непроверенное поведение.

## Цикл ревью и исправлений

В Hermes зависимый цикл: исследование → решение root → worker → tester →
ревью root → исправление существенных замечаний → финальная проверка root.
Root возвращает worker подтверждённые замечания с файлом/строкой, последствиями
и критерием проверки. Tester повторяет затронутые проверки; root проверяет
исправления и новые регрессии до выполнения acceptance criteria.
Отдельный Astra-reviewer не создаётся: `delegate_task` использует одну модель
для всех детей, поэтому reviewer здесь — обязанность root, а не независимый агент.
Простые задачи не требуют отдельного worker/tester. Если цикл не даёт прогресса,
root выясняет причину; останавливается только при блокере вне разрешённого scope.
В Codex применять [цикл tester/reviewer](references/codex.md#цикл-ревью-и-исправлений).
Ни один режим не разрешает merge PR или закрытие issue без явного разрешения
пользователя и выполнения issue-delivery-closure.
