# Роли и цикл Codex

Этот раздел применяется только в Codex. В Hermes используются `delegate_task`
и правила основного SKILL.md; роли и reasoning из `.codex` туда не переносятся.
Настройки: [инструкция проекта](../../../../.codex/README.md).

## Роли

- `explorer`: найти файлы, проследить поток и существующие тесты; только чтение.
- `worker`: реализовать согласованный scope на Luna.
- `tester`: выполнить проверки; менять тесты только по поручению.
- `researcher`: проверить актуальные факты по первичным источникам; только чтение.
- `reviewer`: независимое ревью на Astra; только чтение.

Передавать цель, границы владения файлами, необходимый контекст, ограничения,
критерии готовности и ожидаемый результат. Worker сохраняет чужие изменения;
параллельные исполнители не меняют пересекающиеся файлы.

Использовать настроенные роли без явного переопределения модели и reasoning:
Luna наследует high в большом режиме и medium в экономичном. Не повышать модель
исполнителя без прямого запроса. Глобальные роли других провайдеров не входят
в эту схему. Субагенты не расширяют scope и не делегируют дальше.

## Цикл ревью и исправлений

После реализации tester проверяет поведение, затем reviewer проверяет diff.
Reviewer возвращает результат корневому Astra, а не запускает исполнителей сам.
Для каждого замечания указывает стабильный идентификатор, приоритет, файл и
строку или символ, проблему, последствия, рекомендуемую роль и проверку приёмки.

Root разбирает замечания и назначает только необходимые роли:
- worker исправляет подтверждённую ошибку;
- explorer прослеживает код и область влияния, если причина ещё не установлена;
- researcher уточняет контракт или документацию, если не хватает фактов.

Исследование, от которого зависит исправление, выполняется до worker.
Независимые замечания можно обрабатывать параллельно в пределах общего лимита
и без пересечения файлов. Root передаёт идентификаторы замечаний и критерии
приёмки, переиспользует доступных исполнителей и собирает результаты.

После исправлений tester выполняет релевантные проверки; reviewer повторно
проверяет прежние замечания и новый diff на регрессии. Для каждого замечания
сообщает: устранено, осталось или опровергнуто с доказательством.
Успешные тесты сами по себе не закрывают замечание.

Пока остаются подтверждённые существенные замечания, root повторяет цикл.
Если цикл не даёт прогресса, root разбирает причину и меняет подход; вопрос
пользователю нужен только для решения за пределами scope. После ревью root
интегрирует результат и проверяет обязательные критерии готовности. Merge PR
и закрытие issue выполняет только root по issue-delivery-closure и при явном
разрешении пользователя; этот цикл разрешения не добавляет. Простые задачи
не требуют запуска всех ролей.
